# Generic SOW Template (used only when the partner has no format of their own)

This is the fixed reference structure for Step 1's fallback format. It exists
so that every SOW built without a partner-supplied format looks the same
across runs — same section order, same headings, same placeholder style —
rather than being redrafted from scratch each time. It is a **shape**, not
content: never copy any bracketed placeholder text into a real SOW as if it
were confirmed.

Section order (matches `SKILL.md` Step 1 exactly — if the two disagree,
`SKILL.md` wins):

```
Scope of Work — [Account Name]
Prepared for: [Account Name] | Date: [date] | Reference: [deal/opportunity ID]

1. Background
   [One short paragraph, from the Discovery Summary]

2. Objectives
   [Measurable outcome statements — see SKILL.md Step 4]

3. Requirements & Deliverables
   [Confirmed scope only — see SKILL.md Step 5]

4. Project Approach & Milestones
   [Phased plan — see SKILL.md Step 8A]

5. Dependencies
   [What the customer provides — see SKILL.md Step 6]

6. Out of Scope
   [Short, specific — see SKILL.md Step 7]

7. Indicative Timeline
   [Range only, explicitly labeled indicative — see SKILL.md Step 8]

8. Roles and Responsibilities
   [Partner vs. customer vs. appse ai]

9. Acceptance Criteria
   [One per deliverable, measurable]

10. Change Control
    [How scope changes are requested/approved]

11. Risks & Mitigations
    [Real risks for this scope only]

12. Support & Hypercare
    [Post-go-live window and coverage]

13. Commercial Terms
    [Placeholder line only: "per the accompanying quote/contract"]

14. Open Items to Confirm Before Kickoff
    [Only if present — omit entirely otherwise]
```

## Formatting for the delivered file (Step 11)

- Title page: account name, date, reference — no appse ai branding unless
  the partner supplies their own template with their own branding.
- Section headings use the numbered titles above verbatim.
- Placeholder fields still open at delivery time (`[Customer name]`, etc.)
  must be visually distinct in the file (e.g. bracketed, or highlighted) so
  the partner cannot miss them before sending to the customer — never let a
  placeholder blend in as if it were real content.
- This template only applies when no partner format was given (Step 0). A
  partner-supplied `.docx` format always takes precedence and is filled
  as-is, never replaced with this one.
